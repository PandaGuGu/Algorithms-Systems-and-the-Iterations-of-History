# Algorithms, Systems, and the Iterations of History

一本讲技术的书稿：**算法是对当时机器成本结构的一次回答。硬件改变常数，经济改变选择。所以每隔一代人，同一批算法就要被重新回答一次。**

全书十六章，按四个观察尺度分四部，而不是按时代分期。

| 部 | 观察尺度 | 章 | 主线 |
|---|---|---|---|
| 一 抽象 | 一条指令 → 一段程序 | 1–4 | 人怎样把一件算不清的事交给机器 |
| 二 算法 | 一段程序 → 一台机器 | 5–9 | 成本结构变，同一批算法被重新回答 |
| 三 系统 | 一台机器 → 一组机器 | 10–13 | 成本模型在不同角色手里可见的程度 |
| 四 经济 | 一组机器 → 一个市场 | 14–16 | 谁付钱、谁定标准、哪种解释站得住 |

## 怎么读

**想判断值不值得读**：看第二章（调用栈为什么不是发明出来的）、第六章（理论上的坏消息和好消息，为什么都没改变工程选择）、第十六章（这本书怎样会被证伪）。

**按顺序读**：第一部快读，它是后面所有章节的词汇表；第二部是主干；第三部和第四部可以挑着读。

**只想查东西**：附录 A 是术语表（58 条，每条附"它替换掉的那个直觉说法"），附录 B 是 1947–2024 年表，附录 C 讲证据分级与缺口。

## 证据

书里每出现一个年份、一个型号、一个数量级，背后都该有一条可追溯的出处。

`sources.md` 把证据分三级：**A** 是一手文献（原始论文、当年手册、可复现代码），**B** 是权威二手，**C** 只作线索、不进正文。四条硬规则写在附录 C 里。

有些地方证据没到——EDSAC 的原始指令表、IBM 704 手册页码、云实例价格的时间序列等七处。这些缺口如实列在附录 C 和 `sources.md` 里，正文相应位置用的是限定措辞。**缺口的位置本身也是信息**：它告诉你哪里是断言，哪里是推断。

## 代码

每章末尾有一节"代码"，是把当时机制压缩到能一眼看懂的最小骨架。

这些代码是**示意，不是史料**，也**不报性能数字**。它们的用途只有一个：让"哪一步变了、为什么变"变得可见。要拿去做工程，缺的部分正是工程本身。

## 关于本书的立场

它有一个明确的立场：成本结构解释技术选择。这个立场可以被反驳——第十六章给出了三条可观测的证伪条件，每条都写了量、阈值、观察窗口，以及"什么算没变"。
